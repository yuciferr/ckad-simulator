# 2026-07-07 — Session 11: Unified declarative grading engine + mock/practice parity

## What was implemented

Replaced the brittle, process-mimicry practice grader with a single **declarative, result-oriented** grading engine shared by mock and practice. Previously practice questions had empty `criteria` and were scored by extracting the reference solution's `bash` commands and string-matching them against the student's typed history — so a fully-correct answer to state-persistence Q1 scored **40%** merely because the student named containers `c1/c2` (reference used `busybox2`) and wrote `command:['sh',...]` (reference `/bin/sh`). It now scores **100%**.

### New engine
- `src/client/scoring/checks.ts` — `Check`/`CheckResult` types, `evaluateChecks()`, `scoreFromChecks()`, a dot-path resolver (`[*]`/`[N]`), operators (`exists`/`equals`/`contains`/`count`/`gte`/`has`), tolerant `commandAssertionMatches()` + `tokenInHistory()` (moved out of practice.ts, with k/kubectl + po/pods aliases).
- Each `answer.json` question now carries a `checks: Check[]` array. A check asserts **one** thing against: live cluster state (primary), the student's authored YAML / typed history (fallback), or a `/opt/course` file. Checks assert *requirements* ("2 containers", "replicas=4", "volume at /etc/foo"), never solution-specific names.

### Wiring
- `src/client/scoring/practice.ts` — gutted the bash-parsing; now calls `evaluateChecks`, folds in the namespace signal, renders. Reference solution is now click-to-copy.
- `src/client/scoring/mock.ts` — `autoScoreAll` now runs the same engine; retired the hardcoded per-question heuristics. `screens/review.ts` renders checkboxes from `a.checks` (still manually overridable, still weighted by `q.weight`); copy handlers added to review bodies.
- `src/sandbox/evidence.ts` — also collects student-authored `*.yaml` from the sandbox home dir (`home/` prefix) so shape-checks survive a resource that was created then deleted; and collects cluster-scoped `persistentvolumes`/`storageclasses`.

### UI parity
- Copyable **namespace badge** rendered in `renderQuestion()` (`exam-screen.ts` + `public/index.html` + `style.css`) — practice questions finally show their namespace.
- `attachCopyHandlers` extended to the reference solution, review question/answer bodies, and the namespace badge.

### Content
- Authored `checks` for **all 167 questions**: 150 practice (10 sections) + 17 mock. Applied via a throwaway `scratchpad/apply-checks.js` from per-section data files.

### Validation & tests
- `scripts/validate-exams.js` now validates every `checks` array (label, exactly one assertion source, valid operator, path required for value ops). `exams/answer.schema.json` added; `exams/schema.json` gained `namespace`/`createNamespace`.
- `tests/scoring.test.ts` retargeted from the removed `commandMatches` API to the new engine (11 tests). Full suite: **20 passed**.
- `npm run build`, `npm run lint`, `npm run validate:exams` all green. `make up` rebuilt; `/health` cluster.ready=true; API serves `checks`, HTML serves the badge, `js/scoring/checks.js` 200. Engine validated against realistic k8s JSON (user's failing case → 100%, deleted-pod fallback → 100%, empty → 0%) plus 14 broad path/negative cases.

## Remaining / next
- Browser-driven interactive run (xterm → check answer) was not executed headlessly; engine + API + asset serving were verified instead. Worth a manual smoke test in the UI.
- Command/file-only checks (helm, podman, observability queries, scenario-backed services q9 / observability q4) are intentionally leaner than cluster-state checks — revisit if any prove too lenient/strict in real use.
- Solution `body` text still uses mostly bare `kubectl` commands; the namespace is now shown via the badge, but bodies could later be swept to add `-n <ns>` for completeness.

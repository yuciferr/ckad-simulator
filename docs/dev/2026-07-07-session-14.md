# Session 14 — grading false-negatives + practice progress resume

## Context
User reported (with screenshots) two problems:
1. Correct practice answers being graded wrong (Q3 "env", Q14 "logs -p" in
   core_concepts), and asked to sweep the rest of practice + especially **mock**.
2. Practice progress is persisted but on re-entry a module opens blank (as if
   nothing was solved) and always starts at Q1 instead of where the student
   left off.

## Diagnosis

### Issue 1 — the two screenshot failures were NOT a matcher bug
Built an audit (`scratchpad/audit.mjs`) that runs every `command` check in every
`answer.json` against its OWN reference solution. The core_concepts Q3/Q14
checks *pass* their reference — the live matcher is correct. Those screenshot
failures were the re-entry bug (issue 2): the sandbox reset on re-entry wipes
`.bash_history_q*`, so a re-grade found empty history while the cluster pod
still existed. Fixing issue 2 (restore saved results instead of re-grading empty
history) resolves them.

The audit *did* surface 3 genuinely broken checks:
- `practice/crd` Q2 — required `contains:["stable.example.com"]` in the apply
  command; the group name only ever lives in the student's file, not the
  command. Relaxed to `contains:["-f"]` (reliably verifies "applied a manifest").
- `practice/pod_design` Q42 — `resource:"jobs"` never matched `delete job`
  (singular) because `K8S_TOKEN_ALIASES` had **no job/jobs entry**.
- `practice/pod_design` Q48 — `contains:["cronjob"]` never matched `delete cj`,
  AND it asserted `A CronJob exists` on a task whose end-state is *deleting* the
  cron job (built-in false negative).

### Issue 2 — resume never restored per-module state
`startExam()` only restores from the single-slot `ckad-exam-session` when the
caller passes a `savedSession` (URL-driven resume banner). Clicking a practice
card calls `startExam(examId)` with no session → resets `practiceResults={}` and
`currentQuestion=0`. The single session slot is also overwritten whenever any
other module starts, so it can't durably resume an arbitrary module.

## Changes
- `src/client/scoring/checks.ts` — added `job`/`jobs` (and `cronjobs`) to
  `K8S_TOKEN_ALIASES` so resource-token matching tolerates singular/plural/abbrev.
- `exams/practice/crd/answer.json` Q2 — `stable.example.com` → `-f`.
- `exams/practice/pod_design/answer.json` Q48 — dropped the contradictory
  "A CronJob exists" check; single `Deleted the cron job` check via
  `resource:"cronjob"` (alias covers `cj`).
- `src/client/practice-progress.ts` — new durable per-module store
  (`ckad-practice-detail`): `savePracticeSnapshot()` / `loadPracticeDetail()`
  holding `{ lastQuestion, results }`.
- `src/client/session-persistence.ts` — `saveSession()` now also writes the
  practice snapshot (covers nav / check / flag — every existing save point).
- `src/client/screens/exam-screen.ts` — `startExam()` hydrates
  `state.practiceResults` and `currentQuestion` from the snapshot for practice
  mode when not restoring an explicit session/deep-link.

## Verification
- `audit.mjs` after fixes: **0/115** command checks fail their own reference.
- Targeted matcher tests: singular `delete job`, `describe job`, `delete cj`,
  the Q3/Q14 screenshot commands, and `apply -f` all PASS.
- `npm run build`, `npm run lint`, `validate:exams` (0 err), `validate:scenarios`
  (0 err) all green.
- Reviewed the entire mock `answer.json`: all checks are result-oriented
  (cluster-state) and well-formed; no delete-antipattern or resource-word
  fragility. No mock changes needed.

## Follow-up (same session) — legacy progress backfill
First rebuild still opened Q1 blank. Root cause: the user's existing 16/18 (and
other modules') progress was earned with the OLD code, which wrote ONLY the
status store (`ckad-practice-progress`). The new detailed store
(`ckad-practice-detail`) was empty for that historical data, so there was
nothing to restore — localStorage survives an image rebuild, but the old data
predates the detailed store.

Fix: backfill on entry.
- `src/client/practice-progress.ts` — `resultFromStatus()` reconstructs a
  minimal `PracticeScoreResult` from a stored pass/fail/tried status.
- `src/client/screens/exam-screen.ts` — `startExam()` now merges the detailed
  store (preferred) with the status store (fallback via `resultFromStatus`), so
  pre-existing solved questions re-open as solved. Resume position: use the
  saved pointer when the detailed store has been written (`updatedAt`), else
  resume at the last attempted question.

Verified via a mocked-localStorage simulation (`scratchpad/t3.mjs`): legacy
16/18 → 16 questions restored (100%), resumes at Question 16; a fresh snapshot
round-trips (pointer + new question persisted).

**The user must rebuild the image again** to pick up this backfill.

## Follow-up 2 — resume at first UNSOLVED + responsive layout
User refinements after the resume worked:
1. Resume should land on the first *unsolved* question (2 of 4 solved → open
   Q3), not the last attempted / a saved pointer.
2. The exam/practice split and the review screen weren't responsive — dragging
   the terminal/question divider (or a small window) clipped content.

Changes:
- `src/client/screens/exam-screen.ts` — resume position is now
  `questions.findIndex(q => !results[q.number] || result.scorePercent < passPct)`
  (first not-passed question; all passed → Q1). Replaces the last-attempted /
  pointer logic. Verified across cases in `scratchpad/t4.mjs`.
- `public/style.css` (tracked source, not built):
  - `.panel-left` → `flex-shrink: 0` (dragged width is respected, no clip).
  - `.panel-right` → `min-width: 0; min-height: 0; overflow: hidden` so the
    terminal pane shrinks cleanly instead of forcing overflow ("sığmayan yerler").
  - `@media (max-width: 860px)` stacks question-over-terminal and the review
    screen top/bottom, hides the drag-resizer.
- `src/client/ui.ts` — `initResizer` clamps the left pane to leave ≥320px for
  the terminal, and re-clamps on window resize so a previously-dragged wide pane
  never pushes the terminal off-screen when the window shrinks.

Note: responsive/layout changes were reasoned + build/lint-verified but NOT
visually confirmed in a browser (no browser driver in this env). Worth an eyeball
after rebuild: drag the divider both ways and shrink the window.

# Session 19 — 2026-07-09

## Fixed: mock exam 2 terminal continuously refreshing (CX-7 / CX-5)

### Root cause

`cleanupCurrentExam()` (`src/sandbox/reset.ts`, invoked via `POST
/api/sandbox/cleanup`, called from the client's `backToHome()` — which fires
unconditionally on the very first route resolution of any page load, see
`handleRouteChange` in `src/client/app.ts`) captured `currentExamId` at call
time, awaited the slow `cleanupExamNamespacesFully()` (a `kubectl delete
namespace ... --wait=true` per question), and then **unconditionally** set
the shared `currentExamId = null` once that awaited work finished.

If a *new* `startExam()` legitimately ran while that cleanup was still in
flight (e.g. the student reopens the exam they just left, or reloads while a
previous tab's session was never explicitly torn down), the stale cleanup's
`await` would resolve well after the new session had already set
`currentExamId` again — and then null it out from under the live session,
regardless of what it currently pointed to.

Once `currentExamId` was null, every subsequent terminal `create` computed
`initialNamespaceForQuestion()` with `examId = null`, which short-circuits to
the literal string `'default'` instead of the question's real
`exam-qN` namespace (`src/sandbox/scenario.ts`). Commands then ran against
the wrong namespace, scenario status/reconciliation never lined up with what
the student was looking at, and the terminal effectively became unusable —
matching the reported "continuous refresh, can't type" symptom.

Mock exam 2 has 20 questions (several backed by real manifests) vs. exam 1's
17, so its cleanup pass takes measurably longer, which is why the race was
reliably reproducible on exam 2 in testing and not on exam 1 — same bug,
just a much wider window on the heavier exam.

Reproduced with a scripted Playwright walkthrough of all 20 questions in
mock exam 2 against a real kind cluster; confirmed by inspecting the
per-question kubeconfig files under `sandbox/.kube/config-qN` — from a
certain question onward the `kind-ckad-simulator` context's namespace was
`default` instead of `exam-qN`. Root-caused precisely via targeted debug
instrumentation (temporarily added and fully reverted) that traced every
write to `currentExamId` back to `cleanupCurrentExam`'s post-await
assignment landing after a newer `resetSandboxState()` call.

### Fix

`src/sandbox/reset.ts`: added a `sessionGeneration` counter bumped on every
`resetSandboxState()` call. `cleanupCurrentExam()` now snapshots the
generation before its slow await and only clears `currentExamId` /
`clearLoadedScenarioCache()` if the generation is unchanged when it resumes.
A plain identity check on `currentExamId` isn't sufficient here since
reopening the *same* exam id produces the same string — the generation
counter is what distinguishes "still this session" from "a new session that
happens to share the id" (verified this the hard way: a first attempt that
only guarded on `currentExamId === examId` still failed the repro suite
under looped same-exam-id testing).

### Verification

- 15/15 scripted Playwright walkthroughs of mock exam 2 (all 20 questions,
  typing in the terminal) came back clean post-fix, vs. reliably failing by
  run 2-4 pre-fix.
- 3/3 same walkthrough on mock exam 1 — unaffected, as expected (no
  regression).
- `npm run build`, `npm run lint`, `npm test` all pass.

### Remaining / next

- None outstanding for this issue. The fix is a 2-line behavioral change
  plus a new generation counter; no API or schema changes.

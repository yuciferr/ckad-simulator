# 2026-07-06 — Session 10: Practice exam logical & UI/UX bug sweep

## What was implemented / fixed

Fixed the confirmed logical and UI/UX bugs across `exams/practice/` and the two client bugs
that made the simulator inconsistent. Full plan: `PLAN.md` (repo root).

### UI/UX (client — rebuilt to `public/js/**`, CSS served directly)
- **Terminal half-height** (`public/style.css`): removed a duplicate
  `.terminal-wrapper { position: relative; }` block that overrode the intended
  `position:absolute; inset:0`, collapsing the wrapper to content height and halving the
  terminal. Left a comment so it isn't reintroduced. Also removed a stray `}` after
  `.exam-card.practice .exam-card-badge`.
- **Hint rendered raw ```` ```bash ````** (`src/client/screens/exam-screen.ts`): rewrote
  `bindHintButton`. Added `deriveHintMarkdown()` which pulls the first real command out of the
  answer's first fenced block (skipping blanks/comments), falling back to the first prose line;
  the hint is now rendered through `marked.parse(...)` into `innerHTML` like every other renderer,
  instead of dumping a raw fence delimiter via `textContent`.

### Logical — "create namespace X" pre-created (faithful fix, no pre-create)
- `src/types/exam.ts`: added optional `createNamespace?: boolean` to `ExamQuestion`.
- `src/sandbox/scenario.ts`: `resetQuestionScenario` now consults
  `practiceQuestionCreatesNamespace()`; when a question sets `createNamespace:false` the sandbox
  still deletes for a clean slate but **skips** `kubectl create namespace` (and still marks it
  initialized so later questions in the segment reuse the student-created namespace).
- Set `"createNamespace": false` on the two questions whose graded task is creating their own
  namespace: `core_concepts` Q1 (`mynamespace`), `configuration` Q12 (`limitrange`).
- `scripts/assign-practice-namespaces.js`: documented that it only sets `q.namespace` in place and
  therefore preserves `createNamespace` across reruns (guard note, no logic change needed).

### Content data corruption
- Reconstructed three mangled `body` fields (garbage `…\nweight: N\n\n` prefix + truncated first
  line) from the clean `**Question:**` text in the matching answers, and restored the weights:
  `configuration` Q3 (0→3), Q4 (0→3); `crd` Q3 (0→25).
- `configuration` answer Q15: removed the redundant `kubectl create ns one` step (namespace `one`
  is pre-provisioned, so the command errored `AlreadyExists`). Q12's `create ns limitrange` now
  stays — with `createNamespace:false`, the student really does create it.

### Systematic scan (all 10 topics)
A scripted audit confirmed the above were the only instances of: `weight:0`, `\nweight:` body
artifacts, truncated bodies, and "create namespace X where X == assigned ns". Answer counts match
question counts everywhere; every answer has a code block.

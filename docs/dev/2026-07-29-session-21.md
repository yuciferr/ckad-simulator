### 2. Dead validator check

`scripts/validate-exams.js` warned when a mock namespace had no directory under
`sandbox/etc/kubernetes/mock/` — fixture files from the removed shell-simulation mode.
That path has not existed since the kind migration, so the check emitted 37 unconditional
warnings and drowned real ones. Removed it along with its now-unused imports.
`validate:exams` is now 0 errors / 0 warnings, which makes it usable as a pre-commit gate.

### 3. Pre-existing test failure fixed (mock/1 Q12)

`tests/mock-empty-attempt.test.ts` was red on `main` before this session: an untouched
mock/1 attempt scored 1% instead of 0%.

Cause: Q12 asks the candidate to upgrade `rolling-app` to `httpd:2.4.58-alpine` and then
roll back. The rollback target is *the seeded image*, so a resource check asserting the
final image is `httpd:2.4-alpine` passes identically whether the candidate did the whole
rollout dance or nothing at all — the CX-3 vacuous-pass class.

Fix: replaced that check with command evidence of the step that actually distinguishes
the two states (`set image` + `httpd:2.4.58-alpine`). The rollback itself is already
covered by the `rollout undo` check. 26/26 tests pass.

### 4. `install.sh` now installs what is missing

Previously it *checked* for Docker and told you to go install it. Now it installs it —
`brew install --cask docker` on macOS, the official `get.docker.com` script on Linux
(and adds the user to the `docker` group) — and starts the daemon if it is installed but
not running (`open -a Docker` / `systemctl start docker`), waiting up to 120s for it.

Prompts default to yes and are skipped entirely when stdin is not a TTY or `--yes` is
passed, so `./install.sh --yes` is genuinely unattended. Nothing else is installed on the
host: kubectl, helm and kind all live inside the images.

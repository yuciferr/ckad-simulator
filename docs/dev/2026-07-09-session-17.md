# Session 17 — Fix mock-exam scoring: empty attempt must score 0%

## Context
CX-3: an untouched mock exam (no commands typed, no cluster changes) was
scoring 10–15% instead of 0%. Scoring is the single most critical subsystem
in this project, so the root cause needed pinning down precisely, not
papered over.

## Root cause
`evaluateChecks`/`evalResourceCheck` (`src/client/scoring/checks.ts`) grades
each `answer.json` check against live cluster state. That's correct in
general, but six checks across the two mock exams asserted something that
was **already true from the scenario's `setup.yaml` seed**, independent of
anything the student did:

- Bare `{ resource: 'pods', exists: true }` checks with no `name` — any
  Deployment's ReplicaSet controller creates its Pods the moment the
  scenario is applied, so "pods exist" is true before the student types a
  single command. Found in mock/1 Q1, Q3, Q17 (all fully redundant with a
  more specific check already in the same question — Q17 already asserts
  `status.readyReplicas gte 3`, Q1/Q3 already assert the exact probe fields).
- `equals`/`contains` checks against a field whose seeded starting value
  already matches the target: mock/1 Q12 checked the Deployment image
  `contains: '2.4-alpine'` for a rollback task, but the seed *starts* at
  `httpd:2.4-alpine` — checking the final image can't distinguish "never
  touched" from "rolled back correctly." mock/2 Q8 checked
  `spec.replicas equals 3`, but the seed already ships 3 replicas — the
  actual bug to fix was the container's broken command, not replica count.
  mock/2 Q15 checked that the pre-existing `scaler-app` Deployment
  `exists: true`, which is true from the seed regardless of whether the
  student created the HPA that was the actual point of the question.

Confirmed with a throwaway script (`js-yaml`-parsed each `scenarios/qN/setup.yaml`
into the same `clusterState` shape the real grader consumes, ran
`evaluateChecks` with empty `commands`/`files`) — before the fix, mock/1
scored 1% and mock/2 scored 3% on a fully untouched attempt; the reported
10–15% presumably includes additional live-cluster artifacts (default
ServiceAccount, endpoints, etc.) beyond the static YAML this repro used.

## Fix
`exams/mock/1/answer.json`, `exams/mock/2/answer.json`:
- Removed the three redundant bare `pods exists` checks (Q1, Q3, Q17) —
  each question already has a check that verifies the actual required field.
- Removed the vacuous `Image reverted to httpd:2.4-alpine` check (Q12) —
  the two `command` checks already in that question (`rollout undo`,
  `rollout history`) are the only checks that can prove a rollback
  happened, so the state-only check was pure noise.
- mock/2 Q8: changed `spec.replicas equals 3` → `status.readyReplicas gte 3`.
  Same slot in the checks array, now actually gated on the command fix
  (broken command means the Pods never become Ready, so `readyReplicas`
  stays 0 on an untouched/still-broken attempt).
- mock/2 Q15: changed the `scaler-app` existence check → an assertion that
  the *HPA's* `spec.scaleTargetRef.name` is `scaler-app`. Requires the HPA
  the student was supposed to create, not just the pre-existing Deployment.

No check's grading engine (`src/client/scoring/checks.ts`) needed to change —
this was a data problem in the two answer.json files, not a bug in the
declarative check evaluator itself.

## Tests
Added `tests/mock-empty-attempt.test.ts`: loads each mock exam's real
`exam.json`/`answer.json`, seeds `clusterState` from the real
`scenarios/qN/setup.yaml` files (so pre-seeded Deployments/Pods/etc are
present exactly as they'd be in a live cluster right after scenario setup),
grades with empty `commands`/`files`, and asserts the review-screen's
question-weighted score (mirrors `screens/review.ts` `updateScore()`) is
`0` for both mock/1 and mock/2. Verified the test fails against the
pre-fix answer.json content (1% / 3%) and passes after the fix.

Also spot-checked (ad hoc, not committed) that a fully-correct submission
for Q1/mock1, Q8/mock2, Q15/mock2, and Q17/mock1 still scores 100% —
the fix doesn't introduce false negatives.
